Implementation plan

Environment targets and run filtering

Select a named target in the CLI, record it on every run, and filter run history by that environment.

Complete Revision 2

Decision

Keep definitions local, snapshot results centrally

Environment names and URLs belong in .caracara/config.json, because the CLI owns execution. A run sends the selected name and normalized target URL to Caracara when it starts. Convex stores that snapshot so later URL edits do not rewrite history.

{
  "environments": {
    "development": "http://localhost:3000",
    "production": "https://app.example.com"
  },
  "defaultEnvironment": "development"
}

caracara run --environment production

No hosted environment editor, deployment orchestration, environment table, or environment-specific scenario copies.

Across the change

Global requirements

Requirement

Stable environment identity

Use a lowercase slug such as development or production as the durable filter key. Store the selected key and URL on the run.

Requirement

Safe target URLs

Accept only HTTP or HTTPS URLs without embedded credentials. The selected URL is authoritative for the browser origin even when older prompt text mentions another server.

Phase 01

Environment-aware runs

One vertical change across CLI configuration, run storage, API contracts, and run-history filtering.

Extend the existing run path instead of adding an environment subsystem. Old CLI versions may continue creating runs marked Untracked; no destructive backfill or API namespace bump is needed.

  • CLI selection. Resolve --environment, then CARACARA_ENVIRONMENT, then defaultEnvironment. Reject missing or unknown selections and print the available names.
  • Execution. Open the shared Chromium session at the selected URL and add the name and URL to the runner prompt. Keep one browser session for the full run.
  • Run snapshot. Add optional environment and targetUrl fields to the create-run contract and persist them on runs. Add a project, environment, started-at index for filtered pagination. Existing runs render as Untracked.
  • Frontend. Add an environment select above the run log with All environments plus names derived from stored runs. Filter on the server before pagination, reset the pager when it changes, and show the environment on each row and in run details. Show the snapshotted URL only in details.
  • Specs and docs. Document the config shape, switch command, precedence, run snapshot, legacy behavior, and the rule that credentials stay in secrets.env.

Acceptance checks

CLI

Fast switching

caracara run --environment production uses the production URL for that run without changing the saved default; a plain run uses the configured default.

Frontend

Comparable history

Development and production runs carry visible labels. Selecting one environment returns only that environment across every page, while All includes legacy runs.

Verification

Focused proof

Cover config precedence and URL validation, prompt and browser targeting, API persistence, filtered Convex pagination, legacy runs, and frontend filter state. Then run package tests, typecheck, lint, and build.
